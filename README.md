# 웹카달로그

고객사에 전달하는 품목 카달로그임. 웹에서 품목을 확인하고 PDF 또는 엑셀용 CSV를 다운로드할 수 있음. 영문판의 PDF 버튼은 한글 PDF를 내려받음.

- [한글 웹카달로그](https://suchang-marketing.github.io/catalog/)
- [영문 웹카달로그](https://suchang-marketing.github.io/catalog/en/)
- [원물마스터_최종](https://docs.google.com/spreadsheets/d/1Tqu5GIITbBdmt40LD7OMf3W7fFYJhfKJolebv6IEOns/edit)
- [갱신 실행·결과 확인](https://github.com/suchang-marketing/catalog/actions/workflows/refresh-catalog.yml)

## 자동 갱신

원물마스터_최종을 수정하면 매일 오전 7시경(한국시간) GitHub에서 한글·영문·다운로드용 PDF를 갱신함. 수정 즉시 반영되지는 않으며 GitHub 사정에 따라 늦어질 수 있음. 어느 PC에서든 시트를 수정할 수 있고 별도 프로그램 설치는 필요 없음.

바로 반영하려면 위 갱신 링크 → **Run workflow** → **Branch: main** → **Run workflow**를 누르면 됨. 실행 결과가 초록색이면 발행 완료임. 실행 버튼은 저장소 쓰기 권한이 있는 GitHub 계정으로 로그인해야 보임. 고객사는 로그인 없이 카달로그를 이용할 수 있음.

## 자동 갱신이 안 될 때

1. 갱신 링크에서 최근 실행 결과를 확인함. 아직 실행 중이면 완료될 때까지 기다림.
2. 빨간색으로 실패했다면 해당 실행 → 실패한 단계를 열어 이유를 확인함. 시트 오류를 고친 뒤 **Run workflow**로 다시 실행함. 실패 시 공개 화면은 이전 내용 유지함.
3. 시트를 못 받았다고 나오면 두 연결 시트의 공유 설정이 바뀌었는지 담당자에게 확인함. 시트 탭·열 이름은 임의로 바꾸지 않음.
4. 한글만 바뀌고 영문이 그대로면 해당 실행의 요약 및 **Artifacts → catalog-build-logs → build-report.txt** 확인함. 시트의 영문명·학명을 확인하고, 번역표가 필요한 항목은 담당자가 `en-names.csv`(원물), `en-goods.csv`(상품), `en-terms.csv`(용어)에 추가한 뒤 다시 실행함. 번역표가 시트 값보다 우선함.
5. 최근 실행 자체가 없으면 워크플로가 비활성화됐는지 확인하고 **Enable workflow** 후 실행함. 매일 성공한 실행일을 저장해 공개 저장소의 장기 미활동으로 예약이 꺼지는 것을 방지함.

실행 기록은 30일 보관됨. 실패한 실행을 단순 재실행하면 예전 코드를 사용할 수 있으므로 코드·번역표를 고친 뒤에는 **Run workflow**로 새로 실행함.

## 관리 참고

연결 시트의 원본 CSV와 내부 생성 파일은 저장소나 공개 사이트에 올리지 않음. 공개용 파일만 검사 후 한 번에 발행함. 영문 번역 누락은 영문만 이전 발행본을 유지하며 경고로 표시됨.

자동 갱신은 GitHub가 발급한 임시 권한으로 실행됨. 개인 비밀번호나 개인 액세스 토큰을 저장할 필요 없음. 후임자는 시트 수정 권한과 이 저장소의 쓰기 권한을 인계받으면 됨.
